Every project starts the same way: an empty file and too many tabs open.

This one's a blog. Not because the world needs another one, but because writing things down is the cheapest debugger I know. Half the bugs I've fixed, I fixed while typing out the problem for someone else — usually before I even finished the sentence.

## What this is

A place for the small, specific things: a bug that took four hours and turned out to be a timezone; a refactor that made a file worse before it made it better; a tool that quietly changed how I work.

Nothing here will be a definitive guide. It's a log, not a lecture.

## What this isn't

It isn't going to be polished. Some posts will be three paragraphs. Some will have code that I later realize was wrong. That's fine — the commit history stays visible on purpose.

## Why now

No good reason, honestly. The domain was free, the terminal was open, and `git init` felt easier than the alternative, which was doing nothing.

> The best time to start a changelog was a year ago. The second best time is right after you buy the domain.

More soon.
